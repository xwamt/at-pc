## 🌟 概述

我们非常高兴地宣布 **at-pc v1.1.0** 正式发布！🎉

本次更新是继 v1.0.0 之后的系统性重大演化。重点落地了 **API Key Gate 权限管理体系**、**免预置 Token 的设备免密准入机制（Pending Enrollment）**、**独立 WebSocket 桌面低延迟推流重构**、**跨平台系统常驻托盘** 以及 **全自动化路由安全与文档契约 CI 门禁**。系统在安全性、可靠性与操控延迟体验上均获得质的提升。

---

## 🚀 核心更新与技术亮点

### 1. API Key Gate 安全准入与 RBAC 权限矩阵
- **M0 启动门禁**：对非回环网络强制要求启用 TLS 传输加密；未配置证书且未指定 `--allow-plaintext` 时强制拦截拒启，彻底杜绝明文远程暴露风险；首次启动自动生成引导 Root Key。
- **M1 KeyStore 与多角色 RBAC 矩阵**：
  - 支持签发与管理 `Admin`、`Operator`、`Viewer` 三级权限角色，明确限定 `mcp` 与 `console` 作用域；
  - Web 管理控制台上线“密钥管理（Keys UI）”面板，支持动态生成、吊销及到期轮转密钥；
  - 引入基于客户端 IP 的自适应认证频率限制（失败封锁机制），强力防御网络爆破。
- **M2 设备凭证隔离**：引入专用 `atpc_dv_*` 类型的 Device Token，强绑定 `terminal_id`，禁止跨终端或跨权限复用。
- **M3 会话加固与对抗性闭环**：
  - Web 控制台启用严格 `HttpOnly` Session Cookie；
  - 全量 REST / MCP API 注入 `X-Quota-*` 速率配额感知响应头；
  - 闭环修复 KeyStore 损坏时的 Fail-Closed 熔断保护（P1-24）与多轮对抗性审查漏洞。

### 2. 免预置 Token 的设备待审批准入（Pending Enrollment）
- **密码学设备身份**：Agent 自行生成 Ed25519 硬件密钥对，通过独立 WebSocket 路径（`/enrollment`）发起带签名的注册请求，无需管理员在受控端手动复制或分发 Token。
- **独立待审批存储（DeviceEnrollmentStore）**：
  - 服务端设立与在线终端注册中心物理隔离的待审批存储，未批准设备不能进入在线列表，严格禁止接收任何工具调用、桌面推流与输入事件；
  - 记录设备硬件指纹、核验短语、申请源 IP 及多项元数据，为后续一键批准奠定架构基础。
- **Challenge-Proof 防篡改握手**：设计规范化 `EnrollmentProofTranscript` 防篡改握手协议，防止中间人重放或伪造注册信息。

### 3. 独立 WebSocket 桌面推流与低延迟体验优化
- **Ticket 机制与独立推流通道**：借鉴现代远程桌面架构，引入轻量级 Ticket 验证机制与专用 `/api/desktop/ws` WebSocket 传输管道。
- **推流通道配额豁免**：将桌面流和高频交互事件从常规 API 速率限制中豁免，彻底解决 429 配额耗尽引发的画面冻结与操作卡顿。
- **输入网络防风暴**：压制高频 `mousemove` 降级重试循环，清理前端无用的合成手势工具栏，增加响应头无缓存（`no-cache`）指令，端到端延迟显著下降。

### 4. 跨平台系统常驻托盘与优雅生命周期（System Tray）
- **托盘常驻集成**：基于 `tray-icon`、`muda` 与 `winit`，为 Agent 和 Server 提供跨平台（Windows / macOS）系统托盘图标。
- **关闭拦截与平滑退出**：支持点击窗口关闭按钮自动最小化至系统托盘常驻运行（Close-to-Tray），托盘菜单提供一键断开、手动重连与优雅退出。

### 5. 自动化安全基线与文档契约 CI 门禁
- **静态路由安全扫描（`check_route_security.py`）**：CI 流水线自动化验证全量 HTTP 路由的公开白名单、RBAC 保护、配额头与静态资产沙箱隔离。
- **文档与配置合同检查（`check_documentation_contracts.py`）**：静态保证 README、发布说明、配置文件样本与代码实现严格一致，消除宣传与实现漂移。

## ⚡ 快速上手指南

### 1. 部署与启动中心网关服务端 (Server)

```bash
# 安全默认：仅监听回环地址。生产对外部署请配置 TLS 证书。
./at-pc-server-macos --host 127.0.0.1 --ws-port 9801 --mcp-port 9800

# 访问 Web 控制台（控制台将提示引导 Root Key 或输入 API Key 登录）
open http://localhost:9800/
```

> ⚠️ 注意：若在受限测试网络中监听 `0.0.0.0` 且未开启 TLS，必须显式传递 `--allow-plaintext` 参数。

### 2. 部署与连接受控端 (Agent)

```bash
# 启动受控端 Agent（开启具身操作能力）
./at-pc-agent-macos --server ws://127.0.0.1:9801/ws --enable-computer-use
```

### 3. Cursor / Claude Desktop (MCP 配置)

在 `claude_desktop_config.json` 或 Cursor MCP 配置中接入：

```json
{
  "mcpServers": {
    "at-pc": {
      "command": "/path/to/at-pc-server-macos",
      "args": ["--stdio", "--allow-plaintext"]
    }
  }
}
```
